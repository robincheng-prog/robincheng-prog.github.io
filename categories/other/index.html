Ubuntu 24.04 設定為 HMI

將 Ubuntu 24.04 設定為 HMI（人機介面）系統，主要需要關閉省電、設定自動登入、固定網路 IP、隱藏游標或解鎖觸控與全螢幕自動執行等關鍵設定。

1. 系統電源與螢幕保護設定

工廠或設備的 HMI 需要常亮，不能進入休眠或關閉螢幕。

  • 開啟設定 (Settings) > 電源 (Power)。
  • 將螢幕變暗 (Screen Blank) 設定為從不 (Never)。
  • 關閉自動掛起 (Automatic Suspend) 功能。

2. 設定開機自動登入 (Auto Login)

設備開機後應直接進入 HMI 畫面，不需要手動輸入密碼。

  • 前往設定 (Settings) > 使用者 (Users)。
  • 點擊右上角解鎖（需要輸入密碼）。
  • 開啟自動登入 (Automatic Login) 開關。

3. 固定網路 IP (Static IP)

HMI 通常需透過網卡與 PLC、SCADA 或伺服器穩定通訊。

  • Ubuntu 24.04 使用 Netplan 管理網路。

Windows 11 設定為 HMI

將 Windows 11 設定為工業或專用人機介面（HMI）時，核心目標是確保開機直接進入圖控軟體、關閉干擾通知、防止睡眠與防止操作員亂按系統。

✅ 1. 電源與睡眠設定（防止自動關機或休眠）

HMI 需要 24 小時不間斷運行，絕不能進入省電模式。

  • 進入 設定 > 系統 > 電源與電池。

  • 將「螢幕關閉時間」與「電腦進入睡眠狀態的時間」皆設為 「從不」 (Never)。

  • 檢查控制台的傳統電源選項，確保 PCI Express 或 USB 選擇性暫停功能被停用，避免通訊模組斷線。

✅ 2. 略過登入與自動開機登入（AutoLogon）

開機後必須自動進入桌面並啟動 HMI 軟體，不能卡在密碼輸入畫面。

  • 按下 Win + R 鍵，輸入 netplwiz 並按 Enter。

  • 在跳出的視窗中，取消勾選「必須輸入使用者名稱和密碼，才能使用這台電腦」。

  • 點擊「確定」後，系統會要求你輸入一次目前的帳號與密碼以完成綁定。

✅ 3. 設定 HMI 軟體開機自動執行

讓圖控軟體（如 InTouch、WinCC、KingView 或自寫 SCADA）隨 Windows 啟動。

  • 將你的 HMI 執行檔捷徑，放入 Windows 的啟動資料夾中：

    1. 按下 Win + R，輸入 shell:startup 並按 Enter。

    2. 將 HMI 的捷徑貼到此資料夾中。

✅ 4. 關閉系統更新與干擾通知

避免 HMI 運作中途跳出 Windows 更新重開機或右下角彈出通知。

  • 關閉通知：進入 設定 > 系統 > 通知，將通知總開關設為 關閉，或開啟「專注模式」。

  • 暫緩 Windows 更新：

  • 進入 設定 > Windows 更新，選擇「暫停更新」拉到最長時間（家用/專業版極限）。

  • 若為企業長期穩定需求，建議直接評估使用 Windows 11 IoT Enterprise LTSC 版本並透過群組原則徹底關閉自動更新。

✅ 5. 隱藏介面與防止誤觸（Kiosk 模式或調整工作列）

如果希望操作員只能操作 HMI 畫面，不能點擊桌面或開啟瀏覽器：

  • 自動隱藏工作列：右鍵點選工作列選擇「工作列設定」>「工作列行為」，勾選「自動隱藏工作列」。

  • 鎖定快捷鍵與權限：透過 HMI 軟體自身的帳號權限（如 9 級權限或登入畫面）來管控操作員。如果是單一網頁或 UWP 應用程式，可進一步利用 Windows 11 的 指派存取權 (Assigned Access / Kiosk 模式) 建立單一應用程式鎖定帳戶。

Chrome 網頁型 HMI

由於 Windows 11 內建的「指派存取權 (Kiosk)」選單只強制綁定 Microsoft Edge，無法直接選取 Google Chrome 作為全螢幕 Kiosk 軟體。
既然你的 HMI 是網頁型且指定使用 Chrome，最佳的解決方案是利用 Chrome 內建的 Kiosk 模式（資訊看板模式），並搭配 Windows 的自動開機登入與自訂 Shell (殼層)。這樣操作員開機後，電腦只會跳出 Chrome 且完全隱藏 Windows 桌面與工作列，也無法按 F11 或 Alt+F4 退出。
以下是完整的設定步驟：

🛠️ 第一步：建立專用的 Windows 本地帳戶

為了系統安全與日後維護，請先建立一個獨立的 HMI 操作員帳戶。

  1. 進入 設定 > 帳戶 > 其他使用者。

  2. 點擊「新增帳戶」，選擇「我沒有這名人員的登入資訊」。

  3. 點擊「新增沒有 Microsoft 帳戶的使用者」，輸入名稱（例如：HMI_User），密碼可留空（方便自動登入）。

🔑 第二步：設定該帳戶開機自動登入 (Autologon)

  1. 按下 Win + R 鍵，輸入 netplwiz 並按 Enter。

  2. 取消勾選「必須輸入使用者名稱和密碼，才能使用這台電腦」。

  3. 點擊「確定」後，系統會要求輸入你希望開機自動登入的帳戶（填入 HMI_User）和密碼。

🌐 第三步：建立 Chrome Kiosk 的執行腳本

🔒 第四步：取代 Windows 桌面（修改登錄檔 Shell）

這是最關鍵的一步。我們要讓 HMI_User 這個帳戶登入時，不要載入 Windows 的傳統桌面 (explorer.exe)，而是直接載入我們的 Chrome 腳本。這樣操作員就完全摸不到工作列、開始功能表和桌面。

    HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\IniFileMapping\system.ini\boot

  5. 在 HMI_User 帳戶下，按下 Win + R，輸入 regedit 開啟登錄編輯程式。

  6. 導覽至目前使用者的路徑：
    HKEY_CURRENT_USER\Software\Microsoft\Windows NT\CurrentVersion\Winlogon

  7. 在右側空白處點右鍵 > 新增 > 字串值，命名為 Shell。

  8. 連點兩下剛建立的 Shell，在「數值資料」填入剛才 .bat 檔的絕對路徑：C:\start_hmi.bat。

  • 工程師如何退出進行維護？

    1. 在 HMI 畫面上按下 Ctrl + Alt + Del。

    2. 選擇「登出」或「切換使用者」。

    3. 切換回你的系統管理員帳戶，即可正常使用 Windows 11 桌面進行軟體修改或 PLC 通訊設定。

  5. 點選最下方的「執行 (START)」。如果彈出詢問視窗（例如以 ISO 或 DD 模式寫入），請直接保持預設推薦選項，點選「確定」，等待綠色進度條跑完顯示「準備就緒」。

步驟 3：在隨身碟中配置自動執行檔案

  1. 燒錄完成後，不要拔掉隨身碟。直接在 Windows 的「本機/我的電腦」中打開該隨身碟。
  2. 在隨身碟的根目錄（最上層畫面）中，按滑鼠右鍵「新增」->「資料夾」，命名為 sysrescue.d。
  3. 進入 sysrescue.d 資料夾內，按右鍵「新增」->「文字文件」。將檔案名稱連同副檔名完整修改為 99-autorun.yaml（請確保 Windows 有開啟「顯示副檔名」，不能變成 99-autorun.yaml.txt）。用記事本打開它，貼入上一文字提供的 YAML 內容並儲存。
  4. 依樣畫葫蘆，在同一個地方新增第二個檔案，完整命名為 nvme_erase.sh。用記事本打開，貼入上一文字提供的 Shell 腳本內容並儲存。

💡 檢查點：此時你的隨身碟裡面應該要有一個 sysrescue.d 資料夾，裡面躺著 99-autorun.yaml 和 nvme_erase.sh 兩個檔案。確認無誤後，即可安全彈出隨身碟。

💻 第二階段：在目標電腦上進行清除操作

步驟 4：設定目標電腦由 USB 開機

  1. 將製作好的隨身碟插上那台要清除 SSD 的目標電腦。
  2. 按下電腦電源鍵開機，在畫面亮起的瞬間，連續狂按開機選單快捷鍵（常見廠牌如：ASUS 按 F8、Acer 按 F12、GIGABYTE/聯想 按 F12、MSI 按 F11、HP 按 F9。如果是 DIY 電腦，通常是 F11 或 F12）。
  3. 畫面上會跳出一個小視窗（Boot Menu），用鍵盤上下鍵選擇你的 USB 隨身碟名稱，然後按 Enter。

步驟 5：進入全自動抹除流程

  1. 隨身碟開機成功後，會先看到 SystemRescue 的黑底白字 Grub 啟動選單。直接按 Enter（選擇第一項預設啟動，或放著不管它也會自動倒數進入）。
  2. 電腦會開始跑一堆 Linux 的開機偵測指令（大約需要 15~30 秒，視電腦效能而定）。
  3. 高潮來了： 系統一載入完畢，畫面的所有雜亂文字會被自動清空（Clear），然後立刻彈出你寫的純英文畫面：
  • 標題顯示：🔍 SYSTEMRESCUE AUTO-ERASE ACTIVATED
    • 下方會整齊列出這台電腦上偵測到的 NVMe SSD 裝置路徑、容量與型號。
    • 最下方顯示黃色警告：⚠️ WARNING: ALL DATA ON THE DRIVES ABOVE WILL BE PERMANENTLY ERASED!
  1. 仔細核對畫面上顯示的 SSD 型號是否就是你想清除的那顆。
  2. 確認無誤後，在鍵盤按下 Enter 鍵。
  3. 系統會呼叫內建的硬體指令，這時畫面會顯示 ⚡ Erasing device: /dev/nvme0n1 …。
  4. 大約只需 1~3 秒，畫面就會跳出綠色的 ✅ /dev/nvme0n1 successfully erased!。
  5. 抹除結束後，畫面會跳出 🎉 All tasks finished successfully. Press [Enter] to power off the system…。
  6. 最後再按一次 Enter 鍵，電腦就會自動關機，這時你就可以安全拔下隨身碟，這顆 SSD 的內容已經徹底灰飛煙滅，且完全不傷硬碟健康。

⚠️ 離線操作時的終極排錯（萬一遇到 Erase Failed）

在沒有網路的環境下，如果執行到一半畫面跳出紅色的 ❌ /dev/nvme0n1 erase failed!，這 100% 不是隨身碟壞掉，而是主機板 BIOS 的硬體保護機制造成的。
因為許多主機板為了防止病毒破壞硬碟，開機時會自動把 SSD 狀態鎖定在 “Frozen” (凍結) 狀態，不准任何人發出清除指令。
這時的解決三板斧（照順序嘗試）：

  1. 關閉 BIOS 鎖定：重啟電腦進入 BIOS 設定畫面（通常是按 Del 或 F2），尋找關鍵字如 Security Freeze Lock、SSD Secure Erase Support 或 Block Erase，將其設定為 Disabled (關閉)，存檔重開機即可。
  2. 拔插解鎖法（桌機適用）：當腳本卡在失敗、要求你按 Enter 關機前，直接打開電腦機殼，把那顆 NVMe SSD 的訊號線/電源線拔掉，數 3 秒後再插回去（此動作在 Linux 下會強制重設硬碟狀態並自動解鎖）。拔插好之後，直接在鍵盤按下 Ctrl + C 中斷腳本，然後輸入 bash /run/archiso/bootmnt/sysrescue.d/nvme_erase.sh 重新手動觸發一次即可成功！
  3. 改用 Crypto Erase (加密抹除)：有些新型 SSD 只吃加密抹除（一秒銷毀金鑰）。如果上面方法都失敗，你可以把隨身碟插回 Windows 電腦，用記事本打開 nvme_erase.sh，將裡面第 44 行的 –ses=1 改成 –ses=2，存檔後再去目標電腦跑一次，通常就能順利解決。

自解壓縮執行檔設計方案一

以下方案會發生IExpress 編譯失敗（Exit Code 1）的核心原因：

🔍 失敗原因分析

  1. 權限限制 (UAC Block)：在 Modern Windows (Windows 10/11) 中，iexpress.exe 編譯程序以及 MakeCAB 精靈被歸類為高權限管理工具。如果目前的終端機沒有使用「系統管理員身分 (Administrator)」啟動，IExpress 在寫入報告檔案或呼叫 MakeCAB 指引時會被系統無聲阻擋，導致回傳錯誤碼 1。
  2. 無互動 GUI 阻擋：iexpress.exe 是一個老舊的 GUI 應用程式。在無週邊（Headless）或背景服務容器中，一旦發生編譯或權限錯誤，它會試圖跳出 GUI 錯誤提示視窗而卡死或被強制中斷，因此無法在普通終端機下穩定自動化編譯。

💡 突破性解決方案：Windows 原生 C# 編譯器 (csc.exe)

  • 為了徹底擺脫 IExpress 老舊、高權限要求以及不穩定的缺點，我探索了 Windows 10/11 內建的 .NET C# 編譯器 (csc.exe)。
  • 每台 Windows 電腦在安裝 .NET Framework 時都會內建 csc.exe 編譯器（位於 C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe）。我們可以寫一個極其輕量化的 C# 自解壓啟動程式 Installer.cs，並將工作區的 payload.zip 作為內嵌資源 (Embedded Resource) 編譯進 edat_setup.exe 中！

這樣做有以下巨大優勢：

  • 完全免管理員權限：編譯與生成 edat_setup.exe 不需要任何系統管理員權限。
    100% 原生相容：不依賴 7-Zip 或任何第三方軟體，編譯速度極快且產生的 EXE 非常穩定。
  • 無縫自動化：C# 編譯器是標準的命令列工具，不會像 IExpress 一樣在發生錯誤時彈出 GUI 視窗。
  • 已成功實驗驗證：已在環境中完成小型測試程式的編譯與資源讀取測試，全部順利通過，功能完美運作！
    請查看自解壓縮執行檔設計方案二

本方案詳述如何將 demo 專案中所有的目錄結構與檔案，封裝成一個單一的自解壓安裝檔 (demo_setup.exe)。在執行時，此安裝檔會完整還原工作區的目錄結構，隨後自動調用執行目標批次檔 bin\DC.bat。

由於系統環境，本方案 100% 採用 Windows 10/11 內建的原生封裝技術（IExpress 與 PowerShell）。

🛠️ 架構設計與運作原理

本方案由四個核心元件協同運作：

  1. build.bat (建置指令)：在開發環境中執行的自動化打包腳本。
  2. payload.zip (壓縮內容)：包含 demo 所有程式碼、組件與目錄層級的壓縮檔。
  3. launch.bat (自解壓啟動器)：封裝在安裝檔內的引導腳本，負責執行期解壓縮與呼叫主程式。
  4. setup.sed (IExpress 指引設定)：供 Windows 原生封裝工具 iexpress.exe 讀取的設定檔。

SourceTree 基礎操作教學指南

作者： Ayden

本文件旨在幫助初學者快速上手 SourceTree 的介面與基本功能。SourceTree 是一款強大的 Git 圖形化介面工具，能讓你更直觀地管理程式碼版本。

1. 啟動與倉庫管理 (Repository Management)

在 SourceTree 的初始分頁中，你可以管理你的所有專案。

  • Local (本地): 顯示已存在於你電腦硬碟中的 Git 專案列表。
  • Remote (遠端): 連結 GitHub/GitLab 帳號後，可直接查看雲端上的專案。
  • Clone (複製): 將雲端倉庫（如 GitHub 網址）下載到本地電腦。
  • Add (加入): 將電腦中現有的 Git 資料夾掛載到 SourceTree 列表中。
  • Create (建立): 在指定的資料夾初始化一個全新的 Git 倉庫。

2. 環境設定與 SSH 配置 (Options & SSH)

為了確保能順利提交代碼並與遠端伺服器連線，請確認以下設定：

Tools > Options

  • 使用者資訊 (Default user information):
    • Full Name: 設定你在 Commit 紀錄中顯示的名字。
    • Email Address: 必須與你的 Git 平台（如 GitHub）帳號信箱一致。
  • SSH 客戶端設定: 建議使用 OpenSSH 並正確指向你的私鑰路徑。

3. 遠端倉庫與金鑰指定 (Remote Settings)

當您需要將專案推送到雲端時，必須設定遠端連結路徑，並指定正確的身份驗證金鑰。

Settins > Remotes

  • Remote name: 預設通常為 origin，這是遠端倉庫的代號。
  • URL / Path: 填寫雲端倉庫的位址。
    • 進階技巧: 如果您有多組 SSH Key，可以在路徑前面使用別名（例如 keyB-deploy:帳號/倉庫.git），這能強制 SourceTree 使用您在 config 檔中定義的特定金鑰與該倉庫通訊。
  • Remote Account: 連結特定的主機帳號（如 GitHub），以便進行更深層的整合操作。

4. 工作區介面解析 (File Status View)

當你開啟一個專案後，最常用的就是「File Status」視圖，這裡處理「現在」的改動。

核心區域說明：

  • 左側導覽列: 切換「檔案狀態」、「歷史紀錄」、「分支管理」。
  • 已暫存區 (Staged files): 準備要打包提交的檔案。
  • 未暫存區 (Unstaged files): 電腦中已被修改但尚未打包的檔案。
  • 比對區 (Diff View): 點擊檔案可看具體改動（紅色代表刪除，綠色代表新增）。

5. 頂部工具列詳解 (Action Toolbar)

這是你對 Git 下指令的「動作按鈕區」，也是最核心的控制中心：

  • Commit (提交): 將已暫存 (Staged) 的檔案「打包」並加上訊息備註，存入你電腦的本地紀錄中。
  • Pull (拉取) / Push (推送): * Pull: 從雲端伺服器下載最新的進度到你的電腦。
    • Push: 把你電腦裡的最新紀錄上傳到雲端伺服器分享給他人。
  • Fetch (擷取): 檢查雲端有沒有新東西，但先不自動合併，讓你先掌握遠端動態。
  • Branch (分支) / Merge (合併): * Branch: 建立「平行時空」或開外線來開發新功能，不影響主線。
    • Merge: 將不同分支的開發成果合併在一起。
  • Stash (暫存): 臨時的隱藏區。如果你程式寫到一半必須去處理緊急 Bug，可以用 Stash 將目前改動暫時「藏」起來。
  • Discard (放棄修改): 點擊後會把你選取的檔案改動全部抹除，還原到最後一次存檔的狀態。
  • Tag (標籤): 為特定的 Commit 加上標籤（如 v1.0），方便日後快速回溯。

6. 歷史紀錄與版本溯源 (History View)

「History」視圖讓你查看專案的「過去」。

  • 分支圖 (Graph): 以線條顯示分支的開叉與合併過程。
  • 標籤指示: main 代表本地位置，origin/main 代表雲端位置。

7. 快速操作工作流

  1. 修改: 在編輯器改完存檔。
  2. 暫存: 在 Unstaged files 點擊 + 移至 Staged files。
  3. 提交: 點擊 Commit 並輸入訊息。
  4. 同步: 點擊 Push 上傳至雲端。

本教學由 SourceTree 介面截圖整理而成，適合 Git 入門使用者參考。
