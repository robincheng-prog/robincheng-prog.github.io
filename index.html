如何在 Visual Studio 2022 / 2026 / VS Code 上產生符合歐盟 CRA 規範的 SBOM

本指南說明如何在 Visual Studio (2022 / 2026) 或 Visual Studio Code 開發環境中，使用 CycloneDX .NET CLI 工具為 C# 專案產生符合**歐盟網路彈性法案（EU Cyber Resilience Act, CRA）**要求之 CycloneDX 1.6 格式軟體物料清單（SBOM）。

跨 IDE 與跨版本相容性說明

備註：

本指南中的指令與操作步驟完全相容於 Visual Studio 2022、Visual Studio 2026 以及 Visual Studio Code。

由於 CycloneDX CLI 本質上是透過 .NET SDK（dotnet CLI）獨立運作，並不依賴特定的 IDE 內部引擎，因此無論使用哪一種開發工具或升級版本，命令與流程皆完全一致。

為什麼選擇 CycloneDX 格式？

  • 歐盟 CRA 最佳相容性：原生支援 VEX (Vulnerability Exploitability eXchange)，便於追蹤與標註漏洞可利用性。
  • 符合德國 BSI 指引：德國資訊安全局發布的 TR-03183 指南（針對 CRA SBOM 之具體實施指引）已將 CycloneDX 1.6 列為主要採納標準。
  • 開發者友善：支援輕量化 JSON / XML 格式，適合自動化整合與技術文件歸檔。

1. 系統電源與螢幕保護設定

工廠或設備的 HMI 需要常亮，不能進入休眠或關閉螢幕。

  • 開啟設定 (Settings) > 電源 (Power)。
  • 將螢幕變暗 (Screen Blank) 設定為從不 (Never)。
  • 關閉自動掛起 (Automatic Suspend) 功能。

設備開機後應直接進入 HMI 畫面，不需要手動輸入密碼。

  • 點擊右上角解鎖（需要輸入密碼）。
  • 開啟自動登入 (Automatic Login) 開關。

1. 概述

隨著全球對軟體供應鏈安全的要求日益提高（歐盟網路韌性法案 CRA），提供精確的軟體物料清單 (SBOM) 已成為硬體製造商與韌體開發者的標準要求。

說明如何為 Nuvoton M2354 系列微控制器（支援 Arm TrustZone 技術）的支援包 (BSP) 生成符合 CycloneDX v1.6 規範的 JSON 格式 SBOM，以實現自動化資安漏洞追蹤與授權合規管理。

2. 環境與核心工具準備

要自動化生成 M2354 的 SBOM，您需要準備以下開源 SCA（軟體組成分析）與驗證工具：

  1. Anchore Syft：用於掃描原始碼目錄並生成 SBOM 結構。
    • 安裝 (Linux/macOS): curl -sSfL https://raw.githubusercontent.com/anchore/syft/main/install.sh | sh -s -- -b /usr/local/bin
    • 安裝 (Windows): winget install anchore.syft
  2. CycloneDX CLI：用於驗證生成的 JSON 是否符合國際規範。
    • 下載: 從 CycloneDX 官方 GitHub Releases 獲取對應作業系統的執行檔。
  3. Python 3.8+：用於執行後處理腳本，注入硬體特有屬性與靜態庫雜湊值。

3. 範疇隔離策略 (Scope Policy)

在嵌入式系統開發中，BSP 往往包含了大量測試程式碼、說明文件與範例專案。若將這些檔案一併納入 SBOM，會導致資安掃描時產生大量誤報 (False Positives)。

因此，首要步驟是定義產品範疇 (Product Scope)：

  • 排除 (exclude_path)：不進入生產環境的檔案（如 SampleCode/、Document/）。

嵌入式系統有其特殊的授權與預編譯二進位檔（例如 SmartcardLib 中的 .a 檔）。我們需要透過腳本（通常是 Nuvoton 內部工具或客製化 Python 腳本）將以下屬性注入到基礎 SBOM 中：

Windows 11 設定為 HMI

將 Windows 11 設定為工業或專用人機介面（HMI）時，核心目標是確保開機直接進入圖控軟體、關閉干擾通知、防止睡眠與防止操作員亂按系統。

✅ 1. 電源與睡眠設定（防止自動關機或休眠）

HMI 需要 24 小時不間斷運行，絕不能進入省電模式。

  • 進入 設定 > 系統 > 電源與電池。

  • 將「螢幕關閉時間」與「電腦進入睡眠狀態的時間」皆設為 「從不」 (Never)。

  • 檢查控制台的傳統電源選項，確保 PCI Express 或 USB 選擇性暫停功能被停用，避免通訊模組斷線。

✅ 2. 略過登入與自動開機登入（AutoLogon）

開機後必須自動進入桌面並啟動 HMI 軟體，不能卡在密碼輸入畫面。

  • 按下 Win + R 鍵，輸入 netplwiz 並按 Enter。

  • 在跳出的視窗中，取消勾選「必須輸入使用者名稱和密碼，才能使用這台電腦」。

  • 點擊「確定」後，系統會要求你輸入一次目前的帳號與密碼以完成綁定。

✅ 3. 設定 HMI 軟體開機自動執行

讓圖控軟體（如 InTouch、WinCC、KingView 或自寫 SCADA）隨 Windows 啟動。

  • 將你的 HMI 執行檔捷徑，放入 Windows 的啟動資料夾中：

    1. 按下 Win + R，輸入 shell:startup 並按 Enter。

    2. 將 HMI 的捷徑貼到此資料夾中。

✅ 4. 關閉系統更新與干擾通知

避免 HMI 運作中途跳出 Windows 更新重開機或右下角彈出通知。

  • 關閉通知：進入 設定 > 系統 > 通知，將通知總開關設為 關閉，或開啟「專注模式」。

  • 暫緩 Windows 更新：

  • 進入 設定 > Windows 更新，選擇「暫停更新」拉到最長時間（家用/專業版極限）。

  • 若為企業長期穩定需求，建議直接評估使用 Windows 11 IoT Enterprise LTSC 版本並透過群組原則徹底關閉自動更新。

✅ 5. 隱藏介面與防止誤觸（Kiosk 模式或調整工作列）

如果希望操作員只能操作 HMI 畫面，不能點擊桌面或開啟瀏覽器：

  • 自動隱藏工作列：右鍵點選工作列選擇「工作列設定」>「工作列行為」，勾選「自動隱藏工作列」。

  • 鎖定快捷鍵與權限：透過 HMI 軟體自身的帳號權限（如 9 級權限或登入畫面）來管控操作員。如果是單一網頁或 UWP 應用程式，可進一步利用 Windows 11 的 指派存取權 (Assigned Access / Kiosk 模式) 建立單一應用程式鎖定帳戶。

作者： Ayden

一、 什麼是 SBOM？為什麼我們需要它？

SBOM（Software Bill of Materials） 是軟體的「成分標籤」，詳細記錄了專案中所使用的所有第三方套件、開源元件及版本號。

導入主因：

  1. 合規要求： 歐盟網路韌性法案 (CRA) 等國際法規強制要求產品出廠需具備 SBOM，並有對應的漏洞管理機制。
  2. 零日漏洞快速應變： 當爆發重大資安漏洞（如 Log4j 事件）時，透過掃描 SBOM，能在幾秒鐘內確認我們的產品是否受影響，無須重新編譯原始碼。

二、 團隊標準工作流程 (DevSecOps)

為了保持開發效率並兼顧資安，我們將採用「產出」與「掃描」分離的職責分工模式：

  • 開發團隊： 負責在編譯時，產出正確的 SBOM 檔案。
  • 資安/維運團隊： 拿著 SBOM 檔案進行漏洞比對。

製作與操作流程拆步驟說明。

🛠️ 第一階段：在現有的電腦上製作隨身碟（以 Windows 環境為例）## 步驟 1：準備工具與下載檔案

  1. 準備一支 4GB 或以上容量的隨身碟（注意：製作過程會清空這支隨身碟的資料，請先備份）。
  2. 下載作業系統：前往官方網站下載 SystemRescue 13.2 ISO 映像檔，官方網站下載 SystemRescue ISO 映像檔（選擇相容一般電腦的 x86_64 版本）。
  3. 下載燒錄軟體：下載免安裝的 Rufus 燒錄工具 。

步驟 2：使用 Rufus 燒錄系統

  1. 將隨身碟插上電腦，並打開 Rufus。
  2. 在「裝置 (Device)」欄位，選擇你剛插上的隨身碟。
  3. 在「開機型式 (Boot selection)」欄位右側點選「選擇 (SELECT)」，並選取你剛剛下載的 systemrescue-13.2-amd64.iso 檔案。
  4. 欄位「資料分割方案 (Partition scheme)」選擇 MBR（相容性最高，可支援舊型與新型主機板）；「目標系統 (Target system)」選擇 BIOS 或 UEFI。
  5. 點選最下方的「執行 (START)」。如果彈出詢問視窗（例如以 ISO 或 DD 模式寫入），請直接保持預設推薦選項，點選「確定」，等待綠色進度條跑完顯示「準備就緒」。

步驟 3：在隨身碟中配置自動執行檔案

  1. 燒錄完成後，不要拔掉隨身碟。直接在 Windows 的「本機/我的電腦」中打開該隨身碟。
  2. 在隨身碟的根目錄（最上層畫面）中，按滑鼠右鍵「新增」->「資料夾」，命名為 sysrescue.d。
  3. 進入 sysrescue.d 資料夾內，按右鍵「新增」->「文字文件」。將檔案名稱連同副檔名完整修改為 99-autorun.yaml（請確保 Windows 有開啟「顯示副檔名」，不能變成 99-autorun.yaml.txt）。用記事本打開它，貼入上一文字提供的 YAML 內容並儲存。
  4. 依樣畫葫蘆，在同一個地方新增第二個檔案，完整命名為 nvme_erase.sh。用記事本打開，貼入上一文字提供的 Shell 腳本內容並儲存。

💡 檢查點：此時你的隨身碟裡面應該要有一個 sysrescue.d 資料夾，裡面躺著 99-autorun.yaml 和 nvme_erase.sh 兩個檔案。確認無誤後，即可安全彈出隨身碟。

💻 第二階段：在目標電腦上進行清除操作

步驟 4：設定目標電腦由 USB 開機

  1. 將製作好的隨身碟插上那台要清除 SSD 的目標電腦。
  2. 按下電腦電源鍵開機，在畫面亮起的瞬間，連續狂按開機選單快捷鍵（常見廠牌如：ASUS 按 F8、Acer 按 F12、GIGABYTE/聯想 按 F12、MSI 按 F11、HP 按 F9。如果是 DIY 電腦，通常是 F11 或 F12）。
  3. 畫面上會跳出一個小視窗（Boot Menu），用鍵盤上下鍵選擇你的 USB 隨身碟名稱，然後按 Enter。

步驟 5：進入全自動抹除流程

  1. 隨身碟開機成功後，會先看到 SystemRescue 的黑底白字 Grub 啟動選單。直接按 Enter（選擇第一項預設啟動，或放著不管它也會自動倒數進入）。
  2. 電腦會開始跑一堆 Linux 的開機偵測指令（大約需要 15~30 秒，視電腦效能而定）。
  3. 高潮來了： 系統一載入完畢，畫面的所有雜亂文字會被自動清空（Clear），然後立刻彈出你寫的純英文畫面：
  • 標題顯示：🔍 SYSTEMRESCUE AUTO-ERASE ACTIVATED
    • 下方會整齊列出這台電腦上偵測到的 NVMe SSD 裝置路徑、容量與型號。
    • 最下方顯示黃色警告：⚠️ WARNING: ALL DATA ON THE DRIVES ABOVE WILL BE PERMANENTLY ERASED!
  1. 仔細核對畫面上顯示的 SSD 型號是否就是你想清除的那顆。
  2. 確認無誤後，在鍵盤按下 Enter 鍵。
  3. 系統會呼叫內建的硬體指令，這時畫面會顯示 ⚡ Erasing device: /dev/nvme0n1 …。
  4. 大約只需 1~3 秒，畫面就會跳出綠色的 ✅ /dev/nvme0n1 successfully erased!。
  5. 抹除結束後，畫面會跳出 🎉 All tasks finished successfully. Press [Enter] to power off the system…。
  6. 最後再按一次 Enter 鍵，電腦就會自動關機，這時你就可以安全拔下隨身碟，這顆 SSD 的內容已經徹底灰飛煙滅，且完全不傷硬碟健康。

⚠️ 離線操作時的終極排錯（萬一遇到 Erase Failed）

在沒有網路的環境下，如果執行到一半畫面跳出紅色的 ❌ /dev/nvme0n1 erase failed!，這 100% 不是隨身碟壞掉，而是主機板 BIOS 的硬體保護機制造成的。
因為許多主機板為了防止病毒破壞硬碟，開機時會自動把 SSD 狀態鎖定在 “Frozen” (凍結) 狀態，不准任何人發出清除指令。
這時的解決三板斧（照順序嘗試）：

  1. 關閉 BIOS 鎖定：重啟電腦進入 BIOS 設定畫面（通常是按 Del 或 F2），尋找關鍵字如 Security Freeze Lock、SSD Secure Erase Support 或 Block Erase，將其設定為 Disabled (關閉)，存檔重開機即可。
  2. 拔插解鎖法（桌機適用）：當腳本卡在失敗、要求你按 Enter 關機前，直接打開電腦機殼，把那顆 NVMe SSD 的訊號線/電源線拔掉，數 3 秒後再插回去（此動作在 Linux 下會強制重設硬碟狀態並自動解鎖）。拔插好之後，直接在鍵盤按下 Ctrl + C 中斷腳本，然後輸入 bash /run/archiso/bootmnt/sysrescue.d/nvme_erase.sh 重新手動觸發一次即可成功！
  3. 改用 Crypto Erase (加密抹除)：有些新型 SSD 只吃加密抹除（一秒銷毀金鑰）。如果上面方法都失敗，你可以把隨身碟插回 Windows 電腦，用記事本打開 nvme_erase.sh，將裡面第 44 行的 –ses=1 改成 –ses=2，存檔後再去目標電腦跑一次，通常就能順利解決。

為了將多個獨立檔案中的 packages 與 relationships 陣列進行深度無損合併，我們使用國際大廠 Philips 開源且完美支援 SPDX-2.3 規格的 Philips Software SPDXMerge Tool。

1. 安裝合併工具

在你的電腦終端機（Terminal / CMD）中執行以下指令來下載所需套件：

pip install spdx-tools
pip install spdxmerge

2. 執行深度合併指令

將剛才下載的 NXP 檔案通通放入名為 sbom_inputs 的資料夾內，然後執行：

python -m spdxmerge.SPDXMerge
–docpath “./sbom_inputs”
–outpath “./lpc55s69_combined_project.spdx.json”
–name “LPC55S69_FreeRTOS_Project”
–version “1.0.0”
–mergetype 1
–author “Your Company Name”
–email “developer@example.com“
–filetype J

  • –docpath：放所有 NXP 原始檔案的資料夾路徑。
  • –outpath：合併完成後的最終單一檔案輸出路徑。
  • –mergetype 1：代表 Deep Merge（深度合併），會將所有的相依性組件與其關係無損打包。
  • –filetype J：指定輸出格式為標準 JSON 格式。
