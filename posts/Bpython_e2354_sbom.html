如何使用 python 腳本(process_sbom.py)注入 E2354 SBOM 相關資料

生成這份特定的 m2354bsp_Product_SBOM_cdx.json，必須採用 「Syft 基礎掃描 + 範疇策略過濾 + Python 後處理腳本注入」 的兩階段管道。

因為這份 JSON 除了包含標準的 CycloneDX v1.6 欄位外，還大量包含了常規 SCA 工具無法自動產生的 bsp:* 客製化屬性與靜態庫雜湊值。

以下是重現此 SBOM 的標準實作流程：

步驟一：設定範疇控制政策檔 (product-scope.yaml)

步驟二：使用 Syft 產生 CycloneDX v1.6 基礎檔案

使用與紀錄中相同的工具版本 Anchore Syft v1.45.1，執行目錄掃描並指定輸出規格為 CycloneDX v1.6：

步驟三：執行後處理腳本注入 BSP 特有屬性（Post-Processing）

基礎 Syft 產出的 JSON 缺乏嵌入式軟體特有的屬性，需要撰寫 Python 腳本（如 process_sbom.py）讀取 m2354bsp_raw.json 並注入以下數據：

  • 寫入 metadata 屬性：將主組件設置為 MCU Driver，版本設為 Git Commit 字串，並寫入 bsp:product-scope-include-path 與 bsp:product-scope-exclude-path 等標籤。
  • 元件分類與來源 (bsp:component-origin)：把 StdDriver、Device 等標記為 first-party；將 CMSIS 標記為 third-party。
  • 靜態庫 SHA256 計算：自動掃描 Library/SmartcardLib/ 目錄下的 .a 與 .lib 檔案（如 libsmartcard.a），計算其 SHA256 雜湊並寫入 bsp:static-lib:*:sha256 屬性中。
  • 附加佐證檔案 (Evidence)：針對 Arm CMSIS 組件，寫入 bsp:evidence-file（指向 Document/SBOM/cmsis/sca_cmsis.json）與 bsp:version-evidence（記錄各標頭檔路徑）。
  • 建立依賴關係樹 (dependencies)：建立主產品 04ed2dbaee1fb902 對應至 7 個第一方庫的關聯陣列。
