進一步發揮 Cursor 的威力

學習如何使用 @ 符號精準餵資料給 AI

在 Cursor 中，@ 符號被稱為 Context Mentions（上下文提及）。它是引導 AI 的核心魔法——因為 AI 的回答品質完全取決於你給它的資料（Context）。

如果你只輸入「幫我修這個 Bug」，AI 只能通靈；但如果你加上 @，你就能精準地把專案裡的檔案、甚至官方文件直接塞進 AI 的腦袋裡。

以下為您整理 @ 符號的詳細進階用法與實戰情境：

1. 核心 @ 標籤功能與進階情境

標籤名稱 它是什麼？ 進階實戰情境
@Files 引入特定檔案。 跨檔案對齊邏輯： 當你在寫前端 API 請求時，直接在對話框輸入：「根據 @apiSchema.ts 的型別定義，幫我寫出 @userCard.tsx 裡面的 Fetch 邏輯。」
@Folders 引入整個資料夾。 模組化重構： 當你想讓 AI 學習某個特定模組的架構時：「我想在 @features 裡面新增一個購物車模組，請參考同資料夾下其他功能模組的檔案結構與命名規範。」
@Codebase 讓 AI 掃描整個專案（會自動建立本地索引）。 全局除錯與宏觀分析： 當專案很大、出現莫名報錯時：「在 @Codebase 中，有哪些地方可能導致記憶體洩漏？」 或 「幫我找出目前專案中所有處理 JWT Token 的邏輯並生成報告。」
@Docs 引入第三方官方文件。Cursor 內建了許多熱門框架（如 React, Next.js, Tailwind），你也可以自己貼上任何網站的 URL 讓 Cursor 即時爬取。 使用最新技術 / 拒絕幻覺： 當你在用剛改版的新套件（例如 Next.js 最新架構），AI 的舊知識庫可能不支援。輸入：「使用 @Next.js 的 App Router 新寫法，重構我這段代碼。」 這樣 AI 就絕對不會用舊語法胡謅。

2. 容易被忽略的「高階」@ 隱藏招式

除了檔案和文件，@ 還能綁定許多系統層面的上下文：

💡 @Web（聯網即時搜尋）

  • 用途： 讓 AI 跳出本地端，直接去 Google 搜尋最新解答。
  • 情境： 當你遇到一個剛發布不到幾天的全新 Bug，或是某個第三方 API 剛改版：
  • 指令： 「查一下 @Web 關於這個最新報錯 [貼上報錯訊息]，目前社群有什麼解決方案？」

💡 @Git（版本控制追蹤）

  • 用途： 讓 AI 讀取你的 Git Commit 歷史、Diff（變更內容）或 PR 資訊。
  • 情境：
  • 寫 Commit Message： 寫完代碼懶得想 Commit？輸入 「根據 @Git (Staged Changes) 幫我寫 3 個符合 Conventional Commits 規範的訊息。」
  • 程式碼審查 (Code Review)： 在提交 PR 前，輸入 「請幫我 Review @Git (Current Branch) 的修改，有沒有潛在效能問題？」

💡 @Code / @Definitions（特定程式碼片段）

  • 用途： 精準鎖定某個特定的 Function（函數）或 Class（類別），而不用引入整支大檔案。
  • 情境： 檔案很大（上千行），你只想讓 AI 修改某一小段：
  • 指令： 「請優化 @userService.ts 裡面的 @createUser 函數的防呆邏輯。」

3. 實戰組合技：在 Composer (Ctrl + I) 中發揮最大威力

當你使用多檔案編輯功能（Composer）時，結合多個 @ 標籤可以讓 AI 像資深架構師一樣工作：

終極情境：專案全面 TypeScript 化
你開啟了 Ctrl + I，在輸入框中寫下：
➡️ 「我想把 @legacy_code 資料夾下的所有 JS 檔案轉換成 TS。請參考 @types/global.d.ts 的型別定義，並嚴格遵循 @TypeScript 官方文件的最新 Best Practices。如果有遇到外部 API 呼叫，請對照 @api_config.json。」

這樣一來，AI 同時掌握了舊代碼、本地自訂型別、官方新規範、配置檔四個維度的資訊，寫出來的程式碼幾乎不需要手動修改就能直接執行。

⚠️ @ 符號使用小提示（避坑指南）

  1. 精準度 > 數量： 不要動不動就盲目使用 @Codebase。專案極大時，全局掃描會消耗較多 Token，且因為雜訊多，AI 的回答可能反而變得不夠精準。能用 @Files 或 @Folders 限制範圍時，盡量精準限制。
  2. Docs 自訂功能： 如果你發現某個冷門套件不在 Cursor 預設的 @Docs 清單裡，你可以輸入 @Docs -> 點擊 Add New Doc -> 輸入該套件的文件網址（例如 [https://mongoosejs.com/docs/](https://mongoosejs.com/docs/)），Cursor 會在幾秒鐘內建立好該文件的索引，非常強大！

如何撰寫高效率的 .cursorrules 範本

對於 Python 開發者來說，.cursorrules 同樣是大幅提升開發體驗的秘密武器。Python 雖然寫起來直覺，但因為是動態語言，如果沒有嚴格的規範，AI 很容易寫出型別混亂、排版不一，或是套件版本衝突的程式碼。

以下為您量身打造一份適合 Python 開發者（以 FastAPI / Poetry / Modern Python 3.11+ 為例）的 .cursorrules 範本，以及 Python 專屬的進階心法。

📄 Python 開發 .cursorrules 最佳實踐範本

你可以在 Python 專案的根目錄下建立 .cursorrules，並貼入以下內容：

  • 程式碼風格: 嚴格遵循 PEP 8 規範。一律使用 4 個空格縮進。

  • 命名規範: - 變數與函式: 蛇形命名法 (snake_case)

  • 類別 (Class): 駝峰命名法 (PascalCase)

  • 常數: 全大寫蛇形命名法 (UPPER_CASE_SNAKE)

  • 現代 Python 特性: 優先使用 Python 3.10+ 的新特性，例如使用 | 代替 Optional 或 Union（例如 int | None）。

FastAPI & 非同步最佳實踐

  • 非同步宣告: 凡是涉及資料庫 I/O、外部 API 請求的路由與函式，一律使用 async def，並配合 await。如果是純 CPU 計算或不支援非同步的舊套件，才使用 def。
  • Pydantic 模型: 所有請求 (Request Body) 與回應 (Response Model) 必須建立明確的 BaseModel。
  • 依賴注入: 善用 FastAPI 的 Depends 來管理資料庫 Session 或身份驗證邏輯。

錯誤處理與日誌 (Exception & Logging)

  • 嚴格禁止使用全捕捉的 except:，必須指定明確的異常類型（例如 except ValueError:）。
  • 禁止在程式碼中殘留 print()。所有偵錯與紀錄一律使用 Python 標準庫的 logging（例如 logger.info(), logger.error()）。
