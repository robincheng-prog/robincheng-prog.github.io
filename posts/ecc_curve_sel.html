E2354 Crypto ECC ECDH firmware code 開發分享

main.c 說明 E2354 CRYPTO ECC ECDH 程式的初始化、金鑰產生、共用值計算與驗證方式。用來確認雙方算出的 ECDH 值相同；安全金鑰衍生及訊息驗證的完整安全通訊協定。

編譯時曲線設定

ECC_CURVE_SEL 選擇曲線，程式透過條件編譯設定對應的硬體曲線代碼 ECC_CURVE_TYPE 與位元數 ECC_KEY_SIZE。設定為：

可選代碼及位元數如下：

類型 可選曲線
P-curve P_192、P_224、P_256、P_384、P_521
K-curve K_163、K_233、K_283、K_409、K_571
B-curve B_163、B_233、B_283、B_409、B_571

切換曲線時，應確認該曲線受目標晶片與所用 BSP 驅動支援，且位元數和曲線代碼配對正確。私鑰、公鑰及 ECDH 運算都必須使用同一曲線。

程式各部分

系統、UART 與 CRPT 中斷

  • SYS_Init() 啟用 HIRC，設定核心時脈為 96 MHz，並啟用 UART0 與 CRPT 模組時脈；同時設定 UART0 RX/TX 多功能腳位。
  • DEBUG_PORT_Init() 設定 UART 為 115200 baud、8 資料位、無同位、1 停止位。
  • main() 啟用 CRPT_IRQn 與 ECC 中斷。CRPT_IRQHandler() 將中斷交由 ECC_DriverISR(CRPT) 處理。
  • RNG_Open() 初始化隨機數產生器，之後由 GenPrivateKey() 呼叫 RNG_Random() 取得私鑰候選值。

私鑰產生：GenPrivateKey()

函式先依曲線位元數配置暫存陣列，呼叫 RNG_Random() 取得隨機字，再將每個位元組轉成十六進位字元，形成驅動程式使用的私鑰字串。之後以 ECC_IsPrivateKeyValid() 檢查候選值；不符合時會嘗試調整最高位元組的有效位數並重新檢查，仍不符合則繼續產生候選值。

私鑰字串與座標使用十六進位文字緩衝區。d、d2、Qx、Qy、Qx2、Qy2、k、k2 均配置為 168 bytes，供程式保存結果及字串終止字元。

公鑰產生

分別呼叫：

每次呼叫以私鑰和曲線計算公鑰點，輸出 X、Y 座標。回傳值小於 0 時，印出錯誤訊息並跳到結尾的無限迴圈。

在呼叫前將 SysTick->VAL 歸零，完成後以 0xffffff - SysTick->VAL 計算經過的計數值，並依 CyclesPerUs 換算成毫秒輸出。這是運算時間觀察值，並非完整的效能基準測試。

ECDH 共用值計算與比對

第一個呼叫使用 A 的私鑰與 B 的公鑰；第二個呼叫使用 B 的私鑰與 A 的公鑰。雙方應得到相同的 ECDH 結果。以 strcmp(k, k2) 比較兩個十六進位字串，輸出 Share key match. Test OK 或 Share key mismatch!!。

在ECC_GenerateSecretZ() 將 ECDH 結果輸出為字串；不要把它直接當作已完成衍生、可直接用於所有用途的對稱金鑰。

實際裝置交換時，A 與 B 的私鑰應各自留在本機，只傳送公鑰。以雙方的私鑰及對方公鑰計算共用值，並比較結果。

執行與觀察

將 FW 建置並燒錄至 E2354，透過 UART0、115200 baud 的序列終端機觀察輸出。正常流程會顯示 A、B 的私鑰、公鑰座標、運算時間、兩方共用值，以及最後的比對結果。

限制與安全注意事項

  1. 會將私鑰與共用值印到 UART。 僅適合開發及功能驗證；正式產品不得輸出私鑰或共用秘密，也應在不再需要時清除秘密資料。
  2. 沒有實際交換資料或驗證通訊對象。 正式協定需安全傳送並驗證對端公鑰，以防止中間人攻擊；也需處理不合法或不可信任的對端輸入。
  3. 資料加密流程。 將 ECDH 結果轉成具用途區隔的工作金鑰，再搭配經驗證的加密方案。
  4. 注意 RNG_Random() 的字數限制。 每次最多填入 8 個 32-bit word，且可能以回傳值 0 表示逾時。GenPrivateKey() 忽略該回傳值；預設 P-256 需要 8 words，但選用大於 256 bits 的曲線時，單次呼叫無法填滿其所配置的緩衝區。使用較大曲線前，應先確認並修改隨機數取得策略，且檢查 RNG 呼叫結果。
  5. 確認整體錯誤處理。 檢查 ECC 公鑰與 ECDH 函式的負值回傳，但未檢查 RNG_Open()、RNG_Random() 的結果；正式程式應明確處理初始化或隨機數產生失敗。
