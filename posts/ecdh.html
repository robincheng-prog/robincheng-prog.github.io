密碼學 ECDH 開發流程說明

Elliptic-Curve Diffie-Hellman (ECDH) 密鑰交換協定的開發流程說明。ECDH 是一種基於橢圓曲線密碼學 (ECC) 的匿名密鑰協商協定，允許兩方在不安全的通道上建立共享的機密金鑰。

1. 理解 ECDH 基本原理

在開始開發之前，必須先了解 ECDH 的運作方式：

  • 目標：$A$ 和 $B$ 想要在公開網路上建立一個只有他們兩個人知道的共享密鑰 (Shared Secret)。
  • 橢圓曲線參數：雙方必須同意使用相同的橢圓曲線參數（例如 NIST P-256）。
  • 公私鑰對：
    • 雙方各自生成一個隨機數作為私鑰 ($d$)，其中 $0 < d < n$。
    • 雙方各自計算自己的公鑰 ($Q$)，公式為：
      $$Q = d \times G$$
      （私鑰乘以基點 $G$，這是一個純量乘法運算）。

密鑰交換過程

  1. $A$ 生成私鑰 $d_A$ 和公鑰 $Q_A = d_A \times G$。
  2. $B$ 生成私鑰 $d_B$ 和公鑰 $Q_B = d_B \times G$。
  3. $A$ 和 $B$ 交換各自的公鑰（$Q_A$ 和 $Q_B$）。這可以在不安全的通道上進行。
  4. $A$ 計算共享密鑰：
    $$S_A = d_A \times Q_B$$
  5. $B$ 計算共享密鑰：
    $$S_B = d_B \times Q_A$$

數學證明

$$S_A = d_A \times Q_B = d_A \times (d_B \times G) = (d_A \times d_B) \times G$$
$$S_B = d_B \times Q_A = d_B \times (d_A \times G) = (d_B \times d_A) \times G$$

因此，$S_A = S_B = S$，雙方成功計算出相同的共享密鑰 $S$。

2. 開發流程步驟

以下是開發一個使用 ECDH 系統的典型步驟：

步驟 2.1: 選擇合適的橢圓曲線

不要自己發明曲線！使用標準化且經過廣泛審查的曲線。

  • NIST 曲線：例如 NIST P-256，廣泛用於許多標準中。

步驟 2.2: 選擇密碼學函式庫

避免自己實作核心的橢圓曲線數學運算（純量乘法等），這非常容易出錯且可能產生安全漏洞。請使用成熟的密碼學函式庫：

  • C/C++：OpenSSL, mbedTLS, libsodium (如 P-256), Botan
  • Python：cryptography 模組
  • Java：Bouncy Castle, Java Cryptography Extension (JCE)
  • JavaScript/Node.js：Node.js 內建的 crypto 模組, Web Crypto API

步驟 2.3: 密鑰生成 (Key Generation)

使用選定的函式庫生成使用者的公私鑰對。

注意事項：

  • 隨機數生成：私鑰必須使用密碼學安全的隨機數生成器 (TRNG) 生成，這是系統安全的根基。
  • 安全儲存：妥善保管私鑰，絕對不能洩漏。

步驟 2.4: 公鑰交換

設計系統來交換公鑰。這可以透過各種方式完成（例如透過即時通訊協定傳送）。

步驟 2.5: 計算共享密鑰 (Shared Secret)

  • 收到對方的公鑰後，使用自己的私鑰和對方的公鑰計算共享密鑰。
  • 這個計算結果（通常是一個點的 $X$ 座標）就是原始的共享機密。

步驟 2.6: 使用對稱金鑰加密/解密資料

使用步驟 2.5 生成的對稱金鑰，結合現代的安全對稱加密演算法（如 AES-256），來加密雙方通訊的資料。
