Jetson 架構上順暢跑起 Qwen2.5-Coder 7B

在 Jetson Orin NX (16GB) 上部署 Qwen2.5-Coder-7B 作為 IDE 程式碼自動補全是完全可行且能穩定運行的。16GB 的記憶體非常充裕，能夠完美容納量化模型與補全所需的上下文（KV Cache）。

為了達到最流暢的補全體驗（低延遲、高吞吐），最強烈推薦的部署組合是：Ollama (後端服務) + Continue (VS Code 插件)。

🛠️ 第一步：在 Orin NX 上安裝與啟動 Ollama

Ollama 是目前在邊緣設備上部署 LLM 最簡單且效率極高的工具，它內建支援 Qwen2.5-Coder 系列。

  1. 一鍵安裝 Ollama
    在 Orin NX 的終端機（Terminal）執行官方安裝腳本：

  2. 下載並執行 Qwen2.5-Coder-7B 量化版
    對於 16GB 的 Orin NX，強烈建議使用預設的 INT4 量化版本（約 4.7GB）。它能保留將近 10GB 的記憶體給系統與 IDE 插件的上下文快取，反應速度最快。

    註：首次執行會自動下載，看到對話視窗後代表啟動成功，輸入 /exit 可退出對話。背景服務仍會持續運行，預設監聽 http://localhost:11434（訪問可看到 Ollama is running）。

🌐 遠端伺服器配置（如作為獨立伺服器）

如果您的 Orin NX 是作為獨立伺服器，而您是在另一台電腦（Windows / Mac / Linux）上寫程式，您需要調整 Ollama 的網路設定，讓它允許接受外網連線。

💻 第二步：配置 IDE 插件 (以 VS Code 為例)

為了讓 IDE 能夠像 GitHub Copilot 一樣進行行內自動補全（FIM, Fill-in-the-Middle）和側邊欄聊天，建議使用開源插件 Continue。

  1. 在 VS Code 插件市場搜尋並安裝 Continue。
  2. 點擊 VS Code 左側的 Continue 圖標，點擊右下角的齒輪設定（Open Config），編輯 config.yaml。

⚡ 效能優化與避坑指南

  • 鎖定 Orin NX 最高效能模式：
    Jetson 預設可能會為了省電而降頻。開始寫程式前，請開啟最大功率模式（MAXN）以獲得最低補全延遲：

  • 關於自動補全的延遲感：

    • 7B 模型：在 Orin NX 上的 Tab 補全可能會有約 0.5 ~ 1 秒 的輕微遲滯。
    • 極速建議：若追求「即打即現、完全不卡頓」的體驗，建議將 tabAutocompleteModel 改用 qwen2.5-coder:1.5b（聊天則維持 7B）。1.5B 的生成速度極快，體驗更接近 Copilot：

  • 網路穩定性：
    自動補全對網路延遲非常敏感。強烈建議 Orin NX 與開發電腦都接上實體網路線（Ethernet）。走 Wi-Fi 訊號不穩時，打字補全可能會有明顯卡頓。

  • 測試連線：
    如果 VS Code 沒反應，可在開發電腦瀏覽器輸入 http://<YOUR_ORIN_NX_IP>:11434。若顯示 Ollama is running 代表連線正常；若無法連線，請檢查 Orin NX 防火牆是否開放 11434 通訊埠。
