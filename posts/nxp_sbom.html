NXP LPC55S69 SBOM (軟體物料清單)

針對 NXP LPC55S69 結合 FreeRTOS 的專案，將所有軟體組件的 SBOM 尋找、整合並進行漏洞掃描的完整標準作業流程（SOP）如下：

📌 步驟一：尋找並下載所有 NXP / FreeRTOS 原始 SBOM

NXP 微控制器專案的軟體結構是模組化的，你需要前往官方對應的 GitHub 儲存庫（皆支援 SPDX-2.3 格式），將其根目錄的 SBOM.spdx.json 下載並存放到同一個本地資料夾中（例如名為 sbom_inputs/）：

  1. 下載晶片核心與驅動 SBOM：
  • 進入 NXP mcux-devices-rt 儲存庫 下載 SBOM.spdx.json。這包含 LPC55S69 的暫存器定義、啟動檔與基礎外設驅動。
  1. 下載 FreeRTOS 內核 SBOM：
  • 進入 NXP mcuxsdk-freertos-kernel 儲存庫 下載 SBOM.spdx.json。
  1. 下載 FreeRTOS 外設驅動封裝 SBOM（若有使用）：
  • 進入 NXP mcux-freertos-drivers 儲存庫下載 SBOM.spdx.json。

📌 步驟二：整合多個 JSON 檔為單一專案 SBOM

為了將多個獨立檔案中的 packages 與 relationships 陣列進行深度無損合併，我們使用國際大廠 Philips 開源且完美支援 SPDX-2.3 規格的 Philips Software SPDXMerge Tool。

1. 安裝合併工具

在你的電腦終端機（Terminal / CMD）中執行以下指令來下載所需套件：

pip install spdx-tools
pip install git+https://github.com

2. 執行深度合併指令

將剛才下載的 NXP 檔案通通放入名為 sbom_inputs 的資料夾內，然後執行：

python -m spdxmerge.SPDXMerge
–docpath “./sbom_inputs”
–outpath “./lpc55s69_combined_project.spdx.json”
–name “LPC55S69_FreeRTOS_Project”
–version “1.0.0”
–mergetype 1
–author “Your Company Name”
–email “developer@example.com“
–filetype J

  • –docpath：放所有 NXP 原始檔案的資料夾路徑。
  • –outpath：合併完成後的最終單一檔案輸出路徑。
  • –mergetype 1：代表 Deep Merge（深度合併），會將所有的相依性組件與其關係無損打包。
  • –filetype J：指定輸出格式為標準 JSON 格式。

📌 步驟三：進行 CVE 安全漏洞掃描

得到合併後的 lpc55s69_combined_project.spdx.json 檔案後，你隨時可以使用以下兩種業界主流方式進行資安漏洞與合規性掃描：

選項 A：本地端開源快速掃描（使用 Google OSV-Scanner）

Google OSV-Scanner 是目前對 SPDX-2.3 JSON 支援度極高的開源漏洞掃描工具，能直接串接雲端開源漏洞庫。

  1. 安裝工具：

go install ://github.com

  1. 執行掃描並產出 Markdown 報告：

osv-scanner -L ./lpc55s69_combined_project.spdx.json –output report.md

系統會自動讀取清單中的組件與版本號，比對並產出含有 CVE 編號、漏洞嚴重等級（CVSS）的完整分析報告。

選項 B：NXP 官方整合平台（使用 Timesys Vigiles）

NXP 與資安大廠 Timesys 深度合作，提供專屬的軟體成分分析（SCA）平台：

  1. 前往註冊並登入 Timesys Vigiles 平台。
  2. 在網頁控制台中點擊 Upload SBOM。
  3. 將剛剛合併出來的 lpc55s69_combined_project.spdx.json 拖曳上傳。
  4. Vigiles 儀表板會立刻為你條列出該版本 FreeRTOS 或 NXP 驅動內所含的 CVE 漏洞，並提供建議的修正補丁（Patch）或升級版本指引。
