LPC55S6x 專案自動產出符合 CRA 規範的 SBOM

在 CMake 建置環境下，要針對 LPC55S6x + FreeRTOS 專案自動產出符合 CRA 規範的 SBOM，最推薦的做法是將 SBOM 工具直接整合進 CMakeLists.txt 的建置流程中。

這樣一來，每次在本地或 CI/CD Pipeline 執行 cmake –build 時，系統就會自動掃描原始碼、外部 SDK、FreeRTOS 套件，並輸出最新的 CycloneDX 或 SPDX 檔案。

以下是主流的自動化實作方法：

使用 cdxgen 整合 CMake
cdxgen 是一款強大的開源 SBOM 產生器，它原生支援 CMake 專案。它會透過分析 CMake 的編譯資料庫（compile_commands.json）來精準得知專案實際上用了哪些原始碼與標頭檔，避免微控制器專案中常見的「掃描到一堆沒編譯進去的 SDK 廢code」的問題。

在 CMake 配置（Config）成功後卻沒有在 build 目錄下看到 bom.cyclonedx.json，通常是因為 add_custom_target 預設在執行 cmake –build 時不會被主動觸發。

在 CMake 中，自訂目標（Custom Target）必須要滿足特定條件，或者手動指定才會執行。

另外，針對 C/C++（嵌入式系統） 的專案，cdxgen 還有兩個常見的底層依賴問題會導致它靜悄悄地失敗。請透過以下幾個步驟排查與修正：

核心修正 1：修改 CMake 讓它強制在編譯時執行

原本的 add_custom_target 如果沒有加上 ALL 關鍵字，CMake 預設「不會」自動去跑它，除非你手動敲命令指定該 target。

核心檢查 2：C/C++ 專案必須安裝 Java (cdxgen 限制)

這是使用 cdxgen 處理 C/C++ 專案最常踩的隱形坑。

根據 cdxgen 官方技術文件 規定：要為 C 或 Python 專案生成 SBOM，建置環境必須安裝 Java (建議 >= 21)。

因為 cdxgen 底層分析 C 語言 AST 語法樹的工具是用 Java 寫的。如果系統內沒有 Java，cdxgen 執行時會閃退或不輸出任何東西。
