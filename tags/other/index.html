隨身碟自動清除 NVMe SSD

要做到「單一隨身碟、插上電腦、開機即全自動清除 NVMe SSD」，最完美的解決方案是使用 SystemRescue（一個基於 Arch Linux 修改、專為救援設計的 live 系統）。

以下是完整的製作與設定說明。
-這份針對 SystemRescue 13.2 新版架構的「無網路、一插即蓋、全自動 NVMe 快速抹除隨身碟」完美設定指南。

在 SystemRescue 13.2 版本中，新版必須嚴格使用 autorun.exec 的多層級物件格式。

製作與操作流程拆步驟說明。

🛠️ 第一階段：在現有的電腦上製作隨身碟（以 Windows 環境為例）## 步驟 1：準備工具與下載檔案

  1. 準備一支 4GB 或以上容量的隨身碟（注意：製作過程會清空這支隨身碟的資料，請先備份）。
  2. 下載作業系統：前往官方網站下載 SystemRescue 13.2 ISO 映像檔，官方網站下載 SystemRescue ISO 映像檔（選擇相容一般電腦的 x86_64 版本）。
  3. 下載燒錄軟體：下載免安裝的 Rufus 燒錄工具 。

步驟 2：使用 Rufus 燒錄系統

  1. 將隨身碟插上電腦，並打開 Rufus。
  2. 在「裝置 (Device)」欄位，選擇你剛插上的隨身碟。
  3. 在「開機型式 (Boot selection)」欄位右側點選「選擇 (SELECT)」，並選取你剛剛下載的 systemrescue-13.2-amd64.iso 檔案。
  4. 欄位「資料分割方案 (Partition scheme)」選擇 MBR（相容性最高，可支援舊型與新型主機板）；「目標系統 (Target system)」選擇 BIOS 或 UEFI。
  5. 點選最下方的「執行 (START)」。如果彈出詢問視窗（例如以 ISO 或 DD 模式寫入），請直接保持預設推薦選項，點選「確定」，等待綠色進度條跑完顯示「準備就緒」。

步驟 3：在隨身碟中配置自動執行檔案

  1. 燒錄完成後，不要拔掉隨身碟。直接在 Windows 的「本機/我的電腦」中打開該隨身碟。
  2. 在隨身碟的根目錄（最上層畫面）中，按滑鼠右鍵「新增」->「資料夾」，命名為 sysrescue.d。
  3. 進入 sysrescue.d 資料夾內，按右鍵「新增」->「文字文件」。將檔案名稱連同副檔名完整修改為 99-autorun.yaml（請確保 Windows 有開啟「顯示副檔名」，不能變成 99-autorun.yaml.txt）。用記事本打開它，貼入上一文字提供的 YAML 內容並儲存。
  4. 依樣畫葫蘆，在同一個地方新增第二個檔案，完整命名為 nvme_erase.sh。用記事本打開，貼入上一文字提供的 Shell 腳本內容並儲存。

💡 檢查點：此時你的隨身碟裡面應該要有一個 sysrescue.d 資料夾，裡面躺著 99-autorun.yaml 和 nvme_erase.sh 兩個檔案。確認無誤後，即可安全彈出隨身碟。

💻 第二階段：在目標電腦上進行清除操作

步驟 4：設定目標電腦由 USB 開機

  1. 將製作好的隨身碟插上那台要清除 SSD 的目標電腦。
  2. 按下電腦電源鍵開機，在畫面亮起的瞬間，連續狂按開機選單快捷鍵（常見廠牌如：ASUS 按 F8、Acer 按 F12、GIGABYTE/聯想 按 F12、MSI 按 F11、HP 按 F9。如果是 DIY 電腦，通常是 F11 或 F12）。
  3. 畫面上會跳出一個小視窗（Boot Menu），用鍵盤上下鍵選擇你的 USB 隨身碟名稱，然後按 Enter。

步驟 5：進入全自動抹除流程

  1. 隨身碟開機成功後，會先看到 SystemRescue 的黑底白字 Grub 啟動選單。直接按 Enter（選擇第一項預設啟動，或放著不管它也會自動倒數進入）。
  2. 電腦會開始跑一堆 Linux 的開機偵測指令（大約需要 15~30 秒，視電腦效能而定）。
  3. 高潮來了： 系統一載入完畢，畫面的所有雜亂文字會被自動清空（Clear），然後立刻彈出你寫的純英文畫面：
  • 標題顯示：🔍 SYSTEMRESCUE AUTO-ERASE ACTIVATED
    • 下方會整齊列出這台電腦上偵測到的 NVMe SSD 裝置路徑、容量與型號。
    • 最下方顯示黃色警告：⚠️ WARNING: ALL DATA ON THE DRIVES ABOVE WILL BE PERMANENTLY ERASED!
  1. 仔細核對畫面上顯示的 SSD 型號是否就是你想清除的那顆。
  2. 確認無誤後，在鍵盤按下 Enter 鍵。
  3. 系統會呼叫內建的硬體指令，這時畫面會顯示 ⚡ Erasing device: /dev/nvme0n1 …。
  4. 大約只需 1~3 秒，畫面就會跳出綠色的 ✅ /dev/nvme0n1 successfully erased!。
  5. 抹除結束後，畫面會跳出 🎉 All tasks finished successfully. Press [Enter] to power off the system…。
  6. 最後再按一次 Enter 鍵，電腦就會自動關機，這時你就可以安全拔下隨身碟，這顆 SSD 的內容已經徹底灰飛煙滅，且完全不傷硬碟健康。

⚠️ 離線操作時的終極排錯（萬一遇到 Erase Failed）

在沒有網路的環境下，如果執行到一半畫面跳出紅色的 ❌ /dev/nvme0n1 erase failed!，這 100% 不是隨身碟壞掉，而是主機板 BIOS 的硬體保護機制造成的。
因為許多主機板為了防止病毒破壞硬碟，開機時會自動把 SSD 狀態鎖定在 “Frozen” (凍結) 狀態，不准任何人發出清除指令。
這時的解決三板斧（照順序嘗試）：

  1. 關閉 BIOS 鎖定：重啟電腦進入 BIOS 設定畫面（通常是按 Del 或 F2），尋找關鍵字如 Security Freeze Lock、SSD Secure Erase Support 或 Block Erase，將其設定為 Disabled (關閉)，存檔重開機即可。
  2. 拔插解鎖法（桌機適用）：當腳本卡在失敗、要求你按 Enter 關機前，直接打開電腦機殼，把那顆 NVMe SSD 的訊號線/電源線拔掉，數 3 秒後再插回去（此動作在 Linux 下會強制重設硬碟狀態並自動解鎖）。拔插好之後，直接在鍵盤按下 Ctrl + C 中斷腳本，然後輸入 bash /run/archiso/bootmnt/sysrescue.d/nvme_erase.sh 重新手動觸發一次即可成功！
  3. 改用 Crypto Erase (加密抹除)：有些新型 SSD 只吃加密抹除（一秒銷毀金鑰）。如果上面方法都失敗，你可以把隨身碟插回 Windows 電腦，用記事本打開 nvme_erase.sh，將裡面第 44 行的 –ses=1 改成 –ses=2，存檔後再去目標電腦跑一次，通常就能順利解決。

自解壓縮執行檔設計方案二

本方案詳述如何將 EDAT 專案中所有的目錄結構與檔案，封裝成一個單一的自解壓安裝檔 (edat_setup.exe)。在執行時，此安裝檔會完整還原工作區的目錄結構，隨後自動調用執行目標批次檔 bin\DC.bat。

由於 IExpress 工具過於老舊，在 modern Windows 10/11 中存在長路徑限制、權限阻擋（需要系統管理員權限編譯與執行）等問題，本方案採用更現代、高相容性且免管理員權限的 Windows 原生 .NET C# 編譯器 (csc.exe) 技術來編譯自解壓安裝檔。

🛠️ 架構設計與運作原理

本方案由三個核心元件協同運作：

  1. build.bat (啟動引導)：在開發環境中執行的入口腳本，負責呼叫 PowerShell 建置核心。
  2. build.ps1 (建置核心)：負責清理舊檔、將工作區打包成 payload.zip、產生 C# 自解壓原始碼並呼叫 csc.exe 編譯成 edat_setup.exe。
  3. payload.zip (壓縮內容)：包含 EDAT 所有程式碼、組件與目錄層級的臨時壓縮檔，會被內嵌至編譯產出的 EXE 資源中。

自解壓縮執行檔設計方案一

以下方案會發生IExpress 編譯失敗（Exit Code 1）的核心原因：

🔍 失敗原因分析

  1. 權限限制 (UAC Block)：在 Modern Windows (Windows 10/11) 中，iexpress.exe 編譯程序以及 MakeCAB 精靈被歸類為高權限管理工具。如果目前的終端機沒有使用「系統管理員身分 (Administrator)」啟動，IExpress 在寫入報告檔案或呼叫 MakeCAB 指引時會被系統無聲阻擋，導致回傳錯誤碼 1。
  2. 無互動 GUI 阻擋：iexpress.exe 是一個老舊的 GUI 應用程式。在無週邊（Headless）或背景服務容器中，一旦發生編譯或權限錯誤，它會試圖跳出 GUI 錯誤提示視窗而卡死或被強制中斷，因此無法在普通終端機下穩定自動化編譯。

💡 突破性解決方案：Windows 原生 C# 編譯器 (csc.exe)

  • 為了徹底擺脫 IExpress 老舊、高權限要求以及不穩定的缺點，我探索了 Windows 10/11 內建的 .NET C# 編譯器 (csc.exe)。
  • 每台 Windows 電腦在安裝 .NET Framework 時都會內建 csc.exe 編譯器（位於 C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe）。我們可以寫一個極其輕量化的 C# 自解壓啟動程式 Installer.cs，並將工作區的 payload.zip 作為內嵌資源 (Embedded Resource) 編譯進 edat_setup.exe 中！

這樣做有以下巨大優勢：

  • 完全免管理員權限：編譯與生成 edat_setup.exe 不需要任何系統管理員權限。
    100% 原生相容：不依賴 7-Zip 或任何第三方軟體，編譯速度極快且產生的 EXE 非常穩定。
  • 無縫自動化：C# 編譯器是標準的命令列工具，不會像 IExpress 一樣在發生錯誤時彈出 GUI 視窗。
  • 已成功實驗驗證：已在環境中完成小型測試程式的編譯與資源讀取測試，全部順利通過，功能完美運作！
